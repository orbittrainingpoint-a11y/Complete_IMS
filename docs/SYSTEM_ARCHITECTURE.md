## 3. Data Flow Diagrams

### 3.1 Registration → Invoice → Certificate

```
Staff creates Registration
        │
        ▼
invoices_registration
  registration_number: OT/YY/###
  is_refunded: False
  created_at: now()
        │
        ├──▶ invoices_invoice (linked by FK)
        │         └── invoices_invoicepayment (installments)
        │
        ├──▶ invoices_certificationrequest (UUID token)
        │         - Email sent to client
        │         - Client submits: date + rating + feedback
        │         - Admin reviews and generates certificate
        │
        └──▶ invoices_certificate (issued by admin or auto)
```

### 3.2 CRM SSO

```
Staff clicks "CRM" in ERP sidebar
        │
        ▼
GET /crm-jump/
  → HMAC token = base64url({u: username, t: timestamp}) + sig
        │
        ▼
Redirect: CRM /auto-login?t=<token>
  → CRM verifies sig + age < 90s
  → Creates Flask-Login session
        │
        ▼
CRM dashboard (auto-logged in)

Reverse: CRM → ERP ("Register in ERP" button)
  → HMAC token generated by CRM
  → Redirect: /crm-auth/?t=<token>&crm_id=<id>&fn=&ln=&ph=&em=
  → ERP verifies, creates Django session
  → Redirect: /register/?crm_id=<id>&... (form pre-filled)
```

### 3.3 Certificate Request Flow

```
Registration Detail → "Send Certificate Request"
        │
        ▼
POST /registrations/<pk>/send-cert-request/
  → Creates CertificationRequest(token=uuid4(), status='pending')
  → Emails client: /cert-request/<uuid:token>/
        │
        ▼
Client (no login) fills public form:
  - Completed / Not Completed
  - If Completed: date + class_rating + class_feedback (all required)
POST /cert-request/<uuid:token>/
  → status = 'submitted'
        │
        ▼
Admin: /cert-requests/?status=submitted
  → Reviews: rating (stars), feedback (blue box), completion date
  → Enters: from_date, end_date, grade
POST /cert-requests/<pk>/generate/
  → Certificate created
  → status = 'approved'
```

### 3.4 Refund Flow

```
Registration Detail → "Refund" button
        │
        ▼
POST /registrations/<pk>/refund/
  → Creates Refund(status='pending')
        │
        ▼
Admin/Accounts: /refunds/ → Pending tab
POST /refunds/<pk>/confirm/ (action=confirm)
  → refund.status = 'confirmed'
  → registration.is_refunded = True
  → Refund email sent to client
        │
        ▼
Registration: red REFUNDED banner
Revenue queries: .exclude(registration__is_refunded=True)
```

### 3.5 User Creation + CRM Sync

```
Admin: POST /signup/ (role=sales_executive or sales_manager)
        │
        ▼
Django creates: auth_user + UserProfile
        │
        ▼
sync_user_to_crm():
  pymysql.connect(CRM_DB_HOST, CRM_DB_NAME)
  INSERT INTO crm_users (username, email, role, password_hash, ...)
  using werkzeug generate_password_hash for compatibility
```

## 5. Schema Policy

**Additive-only changes.** Never modify or delete existing columns or tables. Rationale: live production data in `orbit_invoice` must never be disrupted by schema alterations. All v3 features were implemented as new model fields (`AddField`) or new models (`CreateModel`).

## 6. Deployment Stack

```
Internet → Nginx (SSL termination, Let's Encrypt)
              ├── :8001 → gunicorn (3 workers) → Django
              └── :5001 → gunicorn → Flask CRM

Static: Nginx directly serves /staticfiles/
Media:  Nginx directly serves /media/
DB:     MariaDB (localhost:3306, same VPS)
Email:  Gmail SMTP (TLS port 587)
```
